# Project object storage port

Status: adapter seam and local test adapter only. This does not enable durable project storage.

## Contract

The API project layer now defines a provider-neutral `ObjectStore` contract for opaque object keys, byte writes, reads, metadata checks, and deletion. Object keys are validated independently of the provider so callers cannot use absolute paths, traversal segments, backslashes, NUL bytes, or ambiguous empty segments.

## Local adapter

`LocalFileObjectStore` exists only for isolated development and tests. It uses private file permissions, atomic temp-file rename, server-computed SHA-256, expected-checksum verification, and rejects symlinked targets and parent directories.

It is not a production fallback. Do not select it automatically when S3/R2 configuration is missing. Production must fail readiness when durable storage is selected but unavailable.

## Not delivered in this phase

- No S3/R2 SDK or remote adapter.
- No PostgreSQL manifest repository or revision transaction.
- No Builder materialize/commit integration.
- No importer for existing local projects.
- No production storage cutover or deployment.

The next implementation phase must add the official AWS SDK v3 S3 client, an R2-compatible adapter, isolated object-store integration tests, manifest commit semantics, and Builder lifecycle integration. The dependency lockfile must be generated by npm itself; do not hand-edit it.
